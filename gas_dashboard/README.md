# GAS Webダッシュボード セットアップ

`smm3_main_web.py`（親機）を使うと、瞬時電力・積算電力量・電気料金のデータを
[Google Apps Script](https://script.google.com/)（以下GAS）製のダッシュボードへ送信し、
外出先からもスマホ等のブラウザで確認できます。子機と同様、今日／週間／月間の比較グラフ・
時間別表示を見られます。

GASの操作に不慣れな方向けに、画面操作レベルで手順を書いています。
本体の [README.md](../README.md) の「7. Webダッシュボード」からのリンクで
ここに来た想定です。

## 1. プロジェクトを作成する

1. [script.google.com](https://script.google.com) を開き、Googleアカウントでログイン。
2. 左上の「＋ 新しいプロジェクト」をクリック。
3. 「無題のプロジェクト」が開き、`コード.gs` という空のファイルが1つだけある状態になる。

## 2. ファイルをコピーする

このリポジトリの `gas_dashboard/` には4つのソースファイルがありますが、GAS側では
「スクリプトファイル」2つ（Code・History）と「HTMLファイル」1つ（Dashboard）、
それにマニフェスト（appsscript.json）として登録します。

1. **Code.gs**：デフォルトで存在する `コード.gs` を開き、中身を全部削除して
   [`Code.js`](Code.js) の内容をそのままコピー＆ペースト。
2. **History.gs を追加**：左側のファイル一覧の「ファイル」の右の「＋」→「スクリプト」を選択。
   ファイル名を聞かれるので `History` と入力（`.gs` は自動で付く）。中身に
   [`History.js`](History.js) の内容をコピー＆ペースト。
3. **Dashboard（HTML）を追加**：同じく「＋」→「HTML」を選択。ここが一番間違えやすい点です。
   **ファイル名は拡張子なしで必ず `Dashboard` と入力してください。**
   `Code.js` 側が `HtmlService.createTemplateFromFile('Dashboard')` と名指しで参照しているため、
   ファイル名がずれる（`dashboard`、`Dashboard.html` 等）と `Cannot find file` エラーで
   ダッシュボードが表示されません。中身は [`Dashboard.html`](Dashboard.html) の内容をコピー＆ペースト。
4. **マニフェスト（appsscript.json）を合わせる**：左メニューの歯車アイコン「プロジェクトの設定」を開き、
   「"appsscript.json" マニフェスト ファイルをエディタで表示する」にチェックを入れる。
   ファイル一覧に現れた `appsscript.json` を開き、中身を [`appsscript.json`](appsscript.json)
   の内容に置き換える。

保存は `Cmd+S`（または各ファイルのフロッピーアイコン）でOKです。

## 3. デプロイする

1. 右上の「デプロイ」ボタン →「新しいデプロイ」。
2. ダイアログ内、まだ種類を選んでいない状態なら「種類の選択」の歯車アイコンをクリックし
   「ウェブアプリ」を選ぶ。
3. 「実行ユーザー」＝**自分**、「アクセスできるユーザー」＝**全員** を選択して「デプロイ」。
4. **初回はここで承認画面が挟まります**：
   - 「アクセスを承認」→ 自分のGoogleアカウントを選択。
   - 「このアプリは Google で確認されていません」という赤い警告画面が出ますが、
     自分で作成した個人用スクリプトなので問題ありません。「詳細」を開き、
     「（プロジェクト名）に移動（安全ではないページ）」をクリックして進んでください。
   - スプレッドシートへのアクセス等の権限確認画面が出るので「許可」。
   - ここで止まって進めない場合は、上記のどれかをスキップしていないか確認してください。
5. デプロイが完了すると `https://script.google.com/macros/s/.../exec` という形式のURLが
   表示されます。これを控えてください（**このURLは事実上のパスワードです**。詳しくは
   下記「プライバシーに関する注意」参照）。

### コードを修正した後、URLを変えずに更新するには

エディタでコードを直しただけでは、デプロイ済みの `/exec` は古いコードのまま動き続けます
（保存とデプロイは別物です）。**同じURLのまま**更新したい場合は：

「デプロイを管理」→ 該当デプロイの鉛筆（編集）アイコン → 「バージョン」で
「新バージョン」を選択 → 「デプロイ」。

（「新しいデプロイ」を選んでしまうと、URLごと新しく発行されてしまうので注意）

## 4. 親機に設定する

控えたURLを、親機の `config_main.json` の `WEB_GAS_URL` に設定してください
（本体READMEの「4. ファイル構成」、`config_files/config_main.json` のサンプル参照。
設定用Googleスプレッドシート経由でも可）。

**URLの`https://script.google.com/macros/s/`と`/exec`部分は省略可能**です。
`AKfycb...`で始まるデプロイID部分だけを入力すれば、残りは自動的に補われます。
（モックGASや`/dev`版など、標準と異なる送信先を指定したい場合は、従来通りフルURLを
そのまま入力してください。`://`が含まれていればフルURLとして扱われます。）

## 5. 動作確認

`/exec` のURLをブラウザで開くとダッシュボードが表示されます。親機からデータが送られてくると
自動的に埋まっていきます。履歴用のスプレッドシートは初回のデータ受信時に自動作成されます
（GASプロジェクトと同じGoogleアカウントのGoogleドライブ内）。

## プロトコル仕様（自前の親機プログラムから送信する場合）

`smm3_main_web.py` 以外の自作プログラムから、このGASへデータを送りたい場合の仕様です。
`/exec` URLへ `Content-Type: application/json` で `POST` し、body は `type` フィールドで
種別を分岐する共通の形になっています。レスポンスは常に成功時 `200 OK`、本文 `"OK"`（JSON
ではなくプレーンテキスト）です。**GASは内部で302リダイレクトを返す実装のため**、HTTPクライアント
によっては「リダイレクトが処理できない」という例外に見えることがありますが、その時点で
`doPost` 自体は実行済み（＝データは受信済み）なので、リダイレクト例外は失敗として扱わないで
ください（`smm3_main_web.py` 側もこの前提で例外メッセージに `'Redirect'` を含む場合は成功扱い
にしています）。

### `type: 'inst'` — 瞬時電力（推奨：30秒間隔程度）

```json
{ "type": "inst", "watt": 850.0, "amp": 8.5, "muted": false }
```
| フィールド | 型 | 内容 |
|---|---|---|
| `watt` | number | 瞬時電力(W) |
| `amp` | number | 瞬時電流(A) |
| `muted` | boolean | 契約アンペア超過等でミュート表示中かどうか（省略時 false 扱い） |

ダッシュボードの「今」の表示に使われるほか、`watt`・`amp`（`muted`は含まない）が`InstLog`
シートへ1行追記されます。`created`は親機からは送られてこないため、**GAS受信時刻**を
そのまま記録します。直近1年分（既定 `INSTLOG_MAX_ROWS = 1051200` 行）だけをローリング保持し、
超過した古い行は追記のたびに削除されます（`History`シートとは別の保持ポリシー）。
ダッシュボードの瞬時値グラフの表示スコープ（最大7日間）は変わらないため、この保持期間を
伸ばしても表示側の通信量・読み出し時間は増えません（裏取得は常に直近20160行に上限あり）。

### `type: 'cuml'` — 積算電力量（推奨：10分間隔程度）

```json
{ "type": "cuml", "collect": "2026-08-01 00:00:00", "created": "2026-08-09 12:30:00",
  "e_energy": 1234.5, "monthly_e_energy": 210.3, "charge": 6800 }
```
| フィールド | 型 | 内容 |
|---|---|---|
| `collect` | string | 検針日時刻（`YYYY-MM-DD HH:MM:SS`） |
| `created` | string | このデータの時刻（`YYYY-MM-DD HH:MM:SS`） |
| `e_energy` | number | 積算電力量(kWh) |
| `monthly_e_energy` | number | 検針日からの当月積算電力量(kWh) |
| `charge` | number | 検針日からの当月電気料金(円) |

`created`・`e_energy` は History シートへ1行追記されます（同時刻の重複は追記しない）。

### `type: 'backfill'` — 履歴データの後追い送信（過去分のまとめ送り）

```json
{ "type": "backfill",
  "created": ["2026-08-01 00:00:00", "2026-08-01 00:30:00"],
  "e_energy": [1000.0, 1000.5] }
```
| フィールド | 型 | 内容 |
|---|---|---|
| `created` | string[] | 各データ点の時刻（`YYYY-MM-DD HH:MM:SS`）。`e_energy` と同じ長さ・同じ添字が対応 |
| `e_energy` | number[] | 各データ点の積算電力量(kWh) |

**重要な仕様**：
- 配列内の**同じ時刻のデータだけ**を新データで上書きします（それ以外の既存データは保持）。
  日付単位ではなく時刻単位の上書きなので、同じ日を複数チャンク（例：半日ずつ2回）に分けて
  送っても、後のチャンクが前のチャンクを消すことはありません。
- 欠測（メーター交換等）のタイミングでも `e_energy: 0` として送って構いません。GAS側は
  0埋めとして扱い、差分計算で特別扱いしません。
- 1回のリクエストに含める点数に厳密な上限はありませんが、ペイロードサイズとGAS側の実行時間
  （`LockService.waitLock(10000)` で最大10秒待ち）を考慮し、半日（24点）程度を目安に分割する
  ことを推奨します。

### `type: 'boot'` — 起動報告（起動ごとに1回）

```json
{ "type": "boot", "cause": 2 }
```
| フィールド | 型 | 内容 |
|---|---|---|
| `cause` | number | リセット理由コード（`machine.reset_cause()` の値をそのまま送る想定） |

累積再起動回数とタイムスタンプ付きログを恒久保存します（`Reboots` シート）。

### `type: 'config'` — 設定値報告（完全にオプション）

```json
{ "type": "config", "contract": 40 }
```
| フィールド | 型 | 内容 |
|---|---|---|
| `contract` | number | 契約アンペア。ダッシュボードの設定ページに表示用として保存されるだけで、GAS側の計算には使われない |

**この`type`は送らなくても他の機能に一切支障ありません**（送らない場合、契約アンペアの表示欄が
空欄になるだけ）。送る場合も、値が変わった時だけで十分です。

### 無音検知について

`type` を問わず、`doPost` を受信するたびに最終受信時刻を記録しています。この時刻から
10分（600秒）以上更新が無いと、ダッシュボードを開いたときに赤画面表示になります。特別な
`type` やハートビート専用のリクエストは不要で、`inst`/`cuml` 等の通常送信が続いていれば
自動的にクリアされます。

## 親機が止まったとき

親機からのデータが10分以上途絶えると、ダッシュボードを開いたときに**画面全体が暗い赤**になり、
上部に「⚠ 親機からのデータが約N分間途絶えています」と点滅表示されます。判定はデータの
最終受信時刻から計算しているだけなので、特別な設定は不要です。

メールなどで能動的に知らせる仕組みは持っていません。親機はウォッチドッグで自動復帰するため、
次にダッシュボードを開いたときに気づければ十分、という判断です。

## 設定ページ（タブ右端の歯車）

ダッシュボード上部、タブの右端にある歯車から設定ページを開けます。設定は
`PropertiesService` に保存され、**家族など複数人で見ている場合は全員共通**です
（誰かが変えると全員に反映されます）。

| 項目 | 変更 | 内容 |
|---|---|---|
| 警告アンペア（A） | ここで変更 | この値以上になると瞬時画面の数値が赤くなります。親機・子機の警告表示とは独立していて、変更してもこのダッシュボードにしか効きません |
| 契約アンペア（A） | 表示のみ | 正本は設定用スプレッドシートの `CONTRACT_AMPERAGE`。親機が起動時に1回だけ送ってくる値を表示します。スプレッドシートで変更した場合は、親機を再起動すると反映されます |

保存ボタンはありません。入力欄から離れたときと、他のタブへ移ったときに自動保存されます。

なお、この設定ページにはパスワードを設けていません。URLを知っていれば誰でも変更できますが、
変えられて困る値が無いため、あえて簡素にしています。

## プライバシーに関する注意

上記手順の「アクセスできるユーザー＝全員」は、**そのURLを知っていれば誰でも閲覧できる**設定です
（ご家庭の電力使用状況が閲覧可能になります）。GASの仕様上、これより狭く「自分だけ」にすると
外出先のスマホ等からの閲覧もできなくなってしまうため、この方式では避けられないトレードオフです。
URLの取り扱いにはご注意ください（人に送るメッセージやスクリーンショット、公開リポジトリなどに
うっかり含めない、等）。第三者に一時的に見せたい場合は、別のデプロイを作成し、不要になったら
削除することで閲覧をすぐに無効化できます。

## favicon・ホーム画面アイコンについて（任意）

`/exec` を直接開いた場合、ブラウザのタブにはGoogleの汎用アイコンが表示されます。GASの
Web Appは `script.google.com` → `script.googleusercontent.com` へのリダイレクト/サンドボックス
経由で配信される都合上、`Dashboard.html` 側で `<link rel="icon">` を書いても反映されません
（`HtmlService` の `setFaviconUrl()` という専用APIもありますが、SVGを渡すと
`doGet` が例外を起こして画面全体が表示できなくなるため使えません）。

これを回避したい場合は、[`netlify_shell/`](netlify_shell/) にある最小限の静的ページ
（`index.html` が `/exec` をiframeで表示するだけの「外枠」）を
[Netlify](https://www.netlify.com/) 等の無料静的ホスティングにデプロイしてください。

1. `netlify_shell/index.html` を開き、`<iframe src="...">` の
   `https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec` の部分を、
   自分の `/exec` URL（上記手順3で控えたもの）に書き換える。
2. [app.netlify.com](https://app.netlify.com/) にログインし、`netlify_shell/` フォルダを
   そのままドラッグ＆ドロップでデプロイ（ビルド不要の静的サイトなので、これだけで公開されます）。
3. 発行されたNetlifyのURL（お好みでカスタムドメインも設定可）をブックマーク／
   ホーム画面に追加すると、favicon・ホーム画面アイコン・タイトルが正しく表示されます。

この手順はあくまで見た目の改善のための任意項目です。ダッシュボード自体の機能は
`/exec` を直接開くだけで完結しており、Netlifyが無くても動作します。
